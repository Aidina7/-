1. Неге API құжаттамасы керек?

API-ді басқа адамдар қолданады: мобильді әзірлеуші, бот жазатын студент, сыртқы компания. Олар сіздің кодыңызды оқымайды — оларға құжаттама керек: қандай endpoint бар, қандай параметр жіберу керек, жауап қандай, қате болса не келеді.

Word-та қолмен жазылған құжаттама бірнеше аптада ескіреді: код өзгереді, құжат өзгермейді. Шешімі — құжаттаманы кодтан автоматты түрде генерациялау.

2. OpenAPI және Swagger

OpenAPI

REST API-ді сипаттайтын стандарт (JSON немесе YAML файл). Қазіргі нұсқасы — 3.0 / 3.1.

Swagger UI

Спецификациядан интерактивті бет жасайтын құрал: «Try it out» батырмасымен сұрау жіберуге болады.

Swagger Editor

YAML-ды браузерде жазып, бірден көру: editor.swagger.io.

Codegen

Спецификациядан клиент кодын (Python, JS, Kotlin), тесттер мен mock-сервер жасау.

Тарих: бастапқыда барлығы «Swagger» деп аталған; 2016 жылы стандарт OpenAPI деп өзгертілді, ал Swagger — құралдардың атауы болып қалды.

3. Спецификацияның құрылымы

openapi: "3.0.3"
info:                                   # атауы, нұсқасы, сипаттамасы
  title: "Колледж API"
  version: "1.0.0"
servers:                                # API қай мекенжайда
  - url: "http://127.0.0.1:8000"
paths:                                  # endpoint-тер
  "/students/{student_id}":
    get:
      summary: "Бір студент туралы мәлімет"
      tags: ["Студенттер"]
      parameters:
        - name: "student_id"
          in: "path"                    # path | query | header
          required: true
          schema: {type: "integer"}
      responses:
        "200":
          content:
            application/json:
              schema: {"$ref": "#/components/schemas/Student"}
        "404": {description: "Табылмады"}
components:
  schemas:                              # деректер модельдері
    Student: {type: object, properties: {...}}
  securitySchemes:                      # кілт, токен
    ApiKeyAuth: {type: apiKey, in: header, name: X-API-Key}

$ref — сілтеме: Student схемасы бір рет сипатталады да, барлық жауапта қайта пайдаланылады. Схема өзгерсе — бір жерде өзгертеміз.

4. Құжаттаманы кодтан генерациялау

«Code-first» тәсілінде құжаттаманың барлық бөлігі кодта бар ақпараттан алынады:

@api.get("/students/{student_id}", tags=["Студенттер"], responses={404: Error})
def get_student(student_id: int) -> Student:
    """Бір студент туралы мәлімет

    student_id: студенттің нөмірі
    """
    return find_student(student_id)
КодтаСпецификацияда
декоратор @api.get("/students/{student_id}")paths → /students/{student_id} → get
docstring-тің бірінші жолыsummary
student_id: intparameter, in: path, type: integer
Optional[str] = Query(None, "...")parameter, in: query, nullable: true, description
-> Student (dataclass)responses → 200 → $ref Student
responses={404: Error}responses → 404
Field("Тегі мен аты", example=...)схема өрісінің description, example
auth=Truesecurity: ApiKeyAuth, 🔒 белгісі

Практикада сіз осындай декораторды өзіңіз жазасыз: @route("get", "/students/{student_id}", "Бір студент", ["Студенттер"], {200: Student, 404: Error}) — ол функцияны ROUTES тізіміне тіркейді, ал openapi() функцияңыз осы тізімнен спецификация құрады.

Нақты жобаларда: FastAPI (Python) — /docs беті өзі пайда болады; springdoc (Java), Swashbuckle (C#), NestJS Swagger (JS).

«Design-first» тәсілі керісінше: алдымен YAML спецификация жазылып, келісіледі, сосын одан код жасалады. Бірнеше команда бір API-мен жұмыс істегенде ыңғайлы.

5. Сапа және «ескірген» құжаттама

Генерация бар болса да, нашар құжаттама болуы мүмкін: summary жоқ, параметрдің сипаттамасы жоқ, 404 сипатталмаған. Практикада сіз check_spec.py — құжаттаманың «линтерін» өзіңіз жазасыз. Нәтижесі шамамен былай:

python3 check_spec.py
[ҚАТЕ   ] GET /schedule   summary жоқ (функцияға docstring жазыңыз)
[ЕСКЕРТУ] GET /schedule   tags жоқ — Swagger UI-да «default» тобына түседі
[ЕСКЕРТУ] GET /schedule   параметр «day» сипаттамасы жоқ

Жағдаят

Колледж API-іне мобильді қосымша жасайтын сыртқы команда қосылды. Олар күнде: «Қандай endpoint бар, қандай параметр жіберу керек, жауап қандай?» деп сұрайды. Word-тағы құжаттама кодтан әлдеқашан артта қалған. Сіздің міндетіңіз — API-ді құжаттамасы кодтан өзі жасалатындай етіп жазу, ал тексеру скрипті ескірген құжаттаманы өткізбесін.

Жұмыс тәртібі. Барлық файлды нөлден жасайсыз: 1) қандай файл; 2) толық коды; 3) іске қосу; 4) күтілетін нәтиже. Кодты түсініп жазыңыз — қорғауда түсіндіресіз. Mac-та python3, Windows-та python.

Енді спецификацияны қолмен жазбаймыз: app.py ішіндегі модельдер (dataclass), декоратор және функциялардан openapi() функциясы оны өзі жасайды. Сервер /docs бетінде Swagger UI көрсетеді.

Файл: app.py

"""№12 эталон шешімі (студент жазатын нұсқа): Колледж API + кодтан OpenAPI генерациясы."""
import json
import re
from dataclasses import dataclass, field, fields, asdict, MISSING
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from typing import Optional, get_type_hints, get_origin, get_args
from urllib.parse import urlsplit, parse_qs, unquote

ROUTES = []          # барлық endpoint осы тізімге жиналады


def route(method, path, summary, tags, responses, params=None):
    """Декоратор: функцияны және оның құжаттамасын ROUTES тізіміне тіркейді."""
    def deco(fn):
        ROUTES.append({"method": method, "path": path, "fn": fn, "summary": summary,
                       "tags": tags, "responses": responses, "params": params or {}})
        return fn
    return deco


def F(description, example=None, default=MISSING):
    meta = {"description": description, "example": example}
    return field(default=default, metadata=meta) if default is not MISSING else field(metadata=meta)


@dataclass
class Student:
    id: int = F("Студенттің нөмірі", 3)
    name: str = F("Тегі мен аты", "Қасымов Дәулет")
    group: str = F("Топ коды", "ИС 3-1")
    email: Optional[str] = F("Электрондық пошта", "d.kassymov@aec.kz", default=None)


@dataclass
class Error:
    error: str = F("Қатенің сипаттамасы", "Студент табылмады")


STUDENTS = [Student(1, "Әлібек Нұрлан", "ИС 3-1"), Student(2, "Сейітова Аружан", "ИС 3-1"),
            Student(3, "Қасымов Дәулет", "ИС 3-1", "d.kassymov@aec.kz"), Student(4, "Жұмабаев Ерасыл", "ВТ 2-1")]


@route("get", "/students", "Студенттер тізімі", ["Студенттер"], {200: [Student]},
       params={"group": "Топ бойынша сүзгі, мысалы ИС 3-1"})
def list_students(q):
    g = q.get("group")
    return 200, [s for s in STUDENTS if g is None or s.group == g]


@route("get", "/students/{student_id}", "Бір студент", ["Студенттер"], {200: Student, 404: Error},
       params={"student_id": "Студенттің нөмірі"})
def get_student(q):
    for s in STUDENTS:
        if s.id == int(q["student_id"]):
            return 200, s
    return 404, Error("Студент табылмады")


# ---------------- OpenAPI генерациясы ----------------
TYPES = {int: "integer", str: "string", float: "number", bool: "boolean"}


def schema_of(tp, schemas):
    if isinstance(tp, list):                               # [Student] -> массив
        return {"type": "array", "items": schema_of(tp[0], schemas)}
    if get_origin(tp) is not None:                         # Optional[str]
        inner = [a for a in get_args(tp) if a is not type(None)][0]
        return dict(schema_of(inner, schemas), nullable=True)
    if hasattr(tp, "__dataclass_fields__"):
        name = tp.__name__
        if name not in schemas:
            hints = get_type_hints(tp)
            props = {}
            for f in fields(tp):
                props[f.name] = dict(schema_of(hints[f.name], schemas), description=f.metadata["description"])
                if f.metadata.get("example") is not None:
                    props[f.name]["example"] = f.metadata["example"]
            req = [f.name for f in fields(tp) if f.default is MISSING]
            schemas[name] = {"type": "object", "properties": props, "required": req}
        return {"$ref": "#/components/schemas/" + name}
    return {"type": TYPES.get(tp, "string")}


def openapi():
    schemas, paths = {}, {}
    for r in ROUTES:
        params = []
        for name, desc in r["params"].items():
            where = "path" if "{%s}" % name in r["path"] else "query"
            params.append({"name": name, "in": where, "required": where == "path",
                           "description": desc, "schema": {"type": "integer" if name.endswith("_id") else "string"}})
        responses = {}
        for code, model in r["responses"].items():
            responses[str(code)] = {"description": "Сәтті" if code < 300 else "Қате",
                                    "content": {"application/json": {"schema": schema_of(model, schemas)}}}
        paths.setdefault(r["path"], {})[r["method"]] = {
            "summary": r["summary"], "tags": r["tags"], "operationId": r["fn"].__name__,
            "parameters": params, "responses": responses}
    return {"openapi": "3.0.3",
            "info": {"title": "Колледж API", "version": "1.0.0", "description": "Оқу практикасы №12"},
            "servers": [{"url": "http://127.0.0.1:8000"}],
            "paths": paths, "components": {"schemas": schemas}}


SWAGGER = """<!DOCTYPE html><html><head><meta charset="utf-8"><title>Swagger UI</title>
<link rel="stylesheet" href="https://unpkg.com/swagger-ui-dist@5/swagger-ui.css"></head>
<body><div id="ui"></div><script src="https://unpkg.com/swagger-ui-dist@5/swagger-ui-bundle.js"></script>
<script>SwaggerUIBundle({url: "/openapi.json", dom_id: "#ui"});</script></body></html>"""


def to_json(x):
    return [to_json(i) for i in x] if isinstance(x, list) else asdict(x) if hasattr(x, "__dataclass_fields__") else x


class H(BaseHTTPRequestHandler):
    def send(self, code, body, ctype="application/json; charset=utf-8"):
        data = body.encode() if isinstance(body, str) else json.dumps(to_json(body), ensure_ascii=False).encode()
        self.send_response(code)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

    def do_GET(self):
        u = urlsplit(self.path)
        if u.path == "/openapi.json":
            return self.send(200, openapi())
        if u.path == "/docs":
            return self.send(200, SWAGGER, "text/html; charset=utf-8")
        q = {k: v[0] for k, v in parse_qs(u.query).items()}
        for r in ROUTES:
            rx = "^" + re.sub(r"{(\w+)}", r"(?P<\1>[^/]+)", r["path"]) + "$"
            m = re.match(rx, u.path)
            if r["method"] == "get" and m:
                q.update({k: unquote(v) for k, v in m.groupdict().items()})
                return self.send(*r["fn"](q))
        self.send(404, {"error": "endpoint жоқ"})


if __name__ == "__main__":
    print("http://127.0.0.1:8000/docs")
    ThreadingHTTPServer(("127.0.0.1", 8000), H).serve_forever()
  1. app.py файлын жасап, кодты жазыңыз, сақтаңыз.
  2. 1-терминалда: python3 app.py → «http://127.0.0.1:8000/docs».
  3. Браузерде http://127.0.0.1:8000/docs ашыңыз. GET /students → «Try it out» → group: ИС 3-1 → Execute → 200 және үш студент. GET /students/{student_id}: 3 → 200; 99 → 404.
  4. http://127.0.0.1:8000/openapi.json ашып, 1-тапсырмадағы openapi.yaml-мен салыстырыңыз: не бірдей, не өзгеше?
  5. Кодты түсіндіріңіз: @route декораторы не істейді? schema_of() Python типтерін OpenAPI типтеріне қалай айналдырады? Optional[str] неге nullable болады?

Есепке: app.py, Swagger UI скриншоттары (endpoint-тер, Schemas, Try it out: 200 және 404), салыстыру, сұрақтарға жауап.

3-тапсырма. Генерация, сапаны тексеру және жеке нұсқа (20 мин, 30 ұпай)

Файл: gen_openapi.py

import json
from app import openapi

Файл: check_spec.py

import json
import sys

spec = json.load(open("openapi.json", encoding="utf-8"))
errors = 0
for path, ops in spec["paths"].items():
    for method, op in ops.items():
        where = method.upper() + " " + path
        if not op.get("summary"):
            print("ҚАТЕ:", where, "— summary жоқ"); errors += 1
        if not op.get("tags"):
            print("ҚАТЕ:", where, "— tags жоқ"); errors += 1
        if not any(c.startswith("2") for c in op["responses"]):
            print("ҚАТЕ:", where, "— 2xx жауабы жоқ"); errors += 1
        for p in op.get("parameters", []):
            if not p.get("description"):
                print("ҚАТЕ:", where, "— параметр", p["name"], "сипаттамасыз"); errors += 1
        if "{" in path and "404" not in op["responses"]:
            print("ҚАТЕ:", where, "— 404 сипатталмаған"); errors += 1
# drift: файл мен код бірдей ме?
from app import openapi
if openapi()["paths"].keys() != spec["paths"].keys():
    print("ҚАТЕ: openapi.json кодтан артта қалды — gen_openapi.py іске қосыңыз"); errors += 1
print("Қате саны:", errors)
sys.exit(1 if errors else 0)
  1. Екі файлды жасаңыз. 2-терминалда: python3 gen_openapi.py → «openapi.json жасалды, endpoint: 2»; python3 check_spec.py → «Қате саны: 0». Шығу коды: echo $? → 0.
  2. Нұсқаңыз бойынша app.py-ге жаңа endpoint қосыңыз (бұл бөлім — өз жұмысыңыз). Үлгі ретінде get_student функциясын қараңыз: декоратор (жол, summary, tags, responses, params) + функция (статус, нәтиже) қайтарады. Жаңа модель керек болса — @dataclass. info.version-ды 1.1.0-ге өзгертіңіз.
  3. Drift: gen_openapi.py-ді іске қоспай python3 check_spec.py → «ҚАТЕ: openapi.json кодтан артта қалды», шығу коды 1. Енді python3 gen_openapi.py && python3 check_spec.py → «Қате саны: 0».
  4. app.py-ді қайта іске қосып (Ctrl+C → python3 app.py), жаңа endpoint-ті Swagger UI-да «Try it out» арқылы тексеріңіз.
