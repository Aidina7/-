1. Деплоймент деген не?

Деплоймент (deployment, орналастыру) — қосымшаның жаңа нұсқасын серверге жеткізіп, іске қосу процесі. Қолмен жасалса, қадам ұмытылады, қате нұсқа жүктеледі, ал ескі нұсқа сақталмай қалады. Автоматты деплойда барлық қадам бір сценариймен, әр жолы бірдей орындалады.

Құрастыруbuild, артефакт
→
Жеткізуupload, sha256
→
Ауыстыруcurrent → жаңа
→
Қайта іске қосуstop / start
→
Тексеруhealth check
→
Rollbackсәтсіз болса

2. Артефакт және манифест

Серверге жеке файлдар емес, бір артефакт — нұсқаның архиві жеткізіледі. Оған манифест жасалады: нұсқа, файлдар тізімі және sha256 бақылау қосындысы. Серверде қосынды қайта есептеледі: сәйкес келмесе, файл жолда бүлінген — орналастыру тоқтайды.

$ python3 build.py
артефакт: dist/app-1.0.0.zip
файлдар: 3 · VERSION, app.py, static/index.html
sha256: defaea1fcddef742...
Бір артефакт барлық ортаға (test, prod) бірдей жеткізіледі — «тестте жұмыс істеді, prod-та жоқ» жағдайы азаяды.

3. Серверде: нұсқалар және current көрсеткіші

Әр нұсқа өз қалтасына ашылады, ескісінің үстіне жазылмайды. Қай нұсқа жұмыс істеп тұрғанын current көрсеткіші көрсетеді (Linux-та әдетте символдық сілтеме, біздің оқу моделінде current.txt).

server/
├── releases/
│   ├── 1.1.0-20261124-091500/
│   ├── 1.2.0-20261124-100200/
│   └── 2.0.0-20261124-113000/   ← current
├── current.txt                  (2.0.0-20261124-113000)
├── app.pid                      (жұмыс істеп тұрған процесс)
└── deploy.log                   (әр қадам — бір JSON жол)

Ауыстыру — бір файлды өзгерту ғана, сондықтан ол бір сәтте орындалады. Ескі нұсқалар сақталады — кері қайту мүмкін. Дискті толтырмау үшін соңғы бірнеше нұсқа ғана қалдырылады.

4. Health check және rollback

Жаңа нұсқа іске қосылған соң сценарий оның /health бетін бірнеше рет тексереді. Жауап 200 болмаса — нұсқа «ауру»: сценарий өзі алдыңғы нұсқаға қайтады (rollback), ал шығу коды 1 болады.

[13:16:13] HEALTH   1-әрекет: HTTP Error 500
...
[13:16:18] FAIL     broken-20261124-131611 денсаулық тексеруінен өтпеді

5. CI/CD құбыры

CI/CD — код өзгерген сайын автоматты түрде тексеру, құрастыру және орналастыру. Әр қадамның шығу коды тексеріледі: біреуі сәтсіз болса, құбыр тоқтайды, ал сайт ескі нұсқамен жұмысын жалғастырады.

git push
→
Тексеруpy_compile, тесттер
→
Құрастыруbuild.py
→
Орналастыруdeploy.py
→
Smoke-тестбасты бет

Нақты жобаларда: GitHub Actions, GitLab CI, Jenkins — құбыр; scp/rsync — жеткізу; ssh + systemd — қайта іске қосу; Ansible, Docker, Kubernetes — көп серверге орналастыру.

# .github/workflows/deploy.yml (мысал)
- run: python build.py
- run: scp dist/app-*.zip deploy@server:/srv/college/releases/
- run: ssh deploy@server "python3 /srv/college/deploy.py"

# app/app.py — серверге орналастырылатын веб-қосымша (колледж сайты)
import json
import os
import sys
from http.server import BaseHTTPRequestHandler, HTTPServer

HERE = os.path.dirname(os.path.abspath(__file__))
VERSION = open(os.path.join(HERE, "VERSION"), encoding="utf-8").read().strip()
PORT = int(sys.argv[1]) if len(sys.argv) > 1 else 8081


class Handler(BaseHTTPRequestHandler):
    def send(self, code, body, ctype):
        data = body.encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

    def do_GET(self):
        if self.path == "/health":
            ok = VERSION != "broken"
            body = json.dumps({"status": "ok" if ok else "fail", "version": VERSION})
            return self.send(200 if ok else 500, body, "application/json")
        page = open(os.path.join(HERE, "static", "index.html"), encoding="utf-8").read()
        self.send(200, page.replace("{{VERSION}}", VERSION), "text/html; charset=utf-8")

    def log_message(self, *args):
        pass


print("қосымша іске қосылды: нұсқа", VERSION, "порт", PORT, flush=True)
HTTPServer(("127.0.0.1", PORT), Handler).serve_forever()

2-тапсырма. Құрастыру: артефакт және манифест (25 мин, 15 ұпай)

Серверге жеке файлдар емес, бір архив (артефакт) жеткізіледі. Манифест — архивтің «төлқұжаты»: нұсқа, файлдар тізімі және sha256 бақылау қосындысы.

Файл: build.py

# build.py — қосымшаны жеткізуге дайын архивке (артефактқа) жинау
import hashlib
import json
import os
import zipfile

SRC = "app"
VERSION = open(os.path.join(SRC, "VERSION"), encoding="utf-8").read().strip()
os.makedirs("dist", exist_ok=True)
archive = os.path.join("dist", "app-%s.zip" % VERSION)

files = []
with zipfile.ZipFile(archive, "w", zipfile.ZIP_DEFLATED) as z:
    for folder, _, names in os.walk(SRC):
        for name in sorted(names):
            if name.endswith(".pyc"):
                continue
            path = os.path.join(folder, name)
            rel = os.path.relpath(path, SRC).replace("\\", "/")
            z.write(path, rel)
            files.append(rel)

sha = hashlib.sha256(open(archive, "rb").read()).hexdigest()
manifest = {"version": VERSION, "archive": archive, "sha256": sha, "files": files}
with open(os.path.join("dist", "manifest.json"), "w", encoding="utf-8") as f:
    json.dump(manifest, f, indent=2)
print("артефакт:", archive)
print("файлдар:", len(files), "·", ", ".join(files))
print("sha256:", sha[:16] + "...")
  1. python3 build.py → «артефакт: dist/app-1.0.0.zip», «файлдар: 3 · VERSION, app.py, static/index.html», «sha256: ...».
  2. dist/manifest.json файлын ашып, өрістерін түсіндіріңіз.
  3. app/VERSION-ды 1.0.1-ге өзгертіп, қайта құрастырыңыз: dist/ ішінде екі архив, sha256 өзгерді ме? Неге?
  4. VERSION-ды 1.0.0-ге қайтарыңыз. Неге архивті тексеру (sha256) жеткізу кезінде маңызды?

Есепке: build.py, manifest.json мазмұны, екі нұсқаның sha256 салыстыруы.

3-тапсырма. Жеткізу және ауыстыру: deploy.py (25 мин, 20 ұпай)

deploy.py барлық кезеңді ретімен орындайды: артефактты тексеру → server/releases/<нұсқа>-<уақыт>/ қалтасына ашу → ескі процесті тоқтату → current.txt-ті ауыстыру → жаңа нұсқаны іске қосу. Төрт функция әзірге «бос» (заглушка) — оларды 4–5-тапсырмаларда толық кодпен ауыстырасыз.

Файл: deploy.py

# deploy.py — веб-қосымшаны «серверге» автоматты түрде орналастыру
#   python3 deploy.py             -> dist/ ішіндегі артефактты орналастыру
#   python3 deploy.py --status    -> қазір қай нұсқа жұмыс істеп тұр
#   python3 deploy.py --rollback  -> алдыңғы нұсқаға қайту
import hashlib
import json
import os
import shutil
import signal
import subprocess
import sys
import time
import urllib.request
import zipfile

SERVER = "server"                                   # «сервер» — жергілікті қалта
RELEASES = os.path.join(SERVER, "releases")         # барлық нұсқалар осында
CURRENT = os.path.join(SERVER, "current.txt")       # қазіргі нұсқаның аты
PID_FILE = os.path.join(SERVER, "app.pid")          # жұмыс істеп тұрған процестің нөмірі
PORT = 8081


def log(step, message):                     # 5-тапсырмада ауыстырасыз (журнал файлға)
    print("%-8s %s" % (step, message))


def releases():
    """Нұсқалар уақыт бойынша (атауындағы күн-уақыт белгісі бойынша) сұрыпталады."""
    return sorted(os.listdir(RELEASES), key=lambda n: n.split("-", 1)[1])


def current_release():
    if os.path.exists(CURRENT):
        return open(CURRENT, encoding="utf-8").read().strip()
    return None


def upload(manifest):
    """Артефактты тексеріп, server/releases/<нұсқа>-<уақыт>/ қалтасына ашу."""
    data = open(manifest["archive"], "rb").read()
    if hashlib.sha256(data).hexdigest() != manifest["sha256"]:
        raise SystemExit("ҚАТЕ: архивтің sha256 сәйкес емес — файл бүлінген")
    name = "%s-%s" % (manifest["version"], time.strftime("%Y%m%d-%H%M%S"))
    path = os.path.join(RELEASES, name)
    os.makedirs(path)
    with zipfile.ZipFile(manifest["archive"]) as z:
        z.extractall(path)
    log("UPLOAD", "%s -> %s (%d файл)" % (manifest["archive"], path, len(manifest["files"])))
    return name


def switch(name):
    with open(CURRENT, "w", encoding="utf-8") as f:
        f.write(name)
    log("SWITCH", "current -> " + name)


def stop_app():
    if not os.path.exists(PID_FILE):
        return
    pid = int(open(PID_FILE).read())
    try:
        os.kill(pid, signal.SIGTERM)
        log("STOP", "ескі процесс тоқтатылды (pid %d)" % pid)
    except OSError:
        pass
    os.remove(PID_FILE)
    time.sleep(0.5)


def start_app(name):
    folder = os.path.join(RELEASES, name)
    out = open(os.path.join(folder, "app.log"), "w")
    proc = subprocess.Popen([sys.executable, "app.py", str(PORT)], cwd=folder, stdout=out, stderr=out)
    with open(PID_FILE, "w") as f:
        f.write(str(proc.pid))
    log("START", "%s іске қосылды (pid %d, порт %d)" % (name, proc.pid, PORT))
    time.sleep(1)


def health_check(tries=5):                  # 4-тапсырмада ауыстырасыз
    return True


def rollback(previous):                     # 4-тапсырмада ауыстырасыз
    return False


def cleanup(keep=3):                        # 5-тапсырмада ауыстырасыз
    pass


def deploy():
    manifest = json.load(open(os.path.join("dist", "manifest.json"), encoding="utf-8"))
    log("BEGIN", "орналастыру басталды: нұсқа " + manifest["version"])
    previous = current_release()
    name = upload(manifest)
    stop_app()
    switch(name)
    start_app(name)
    if health_check():
        log("DONE", "сәтті: %s жұмыс істеп тұр — http://127.0.0.1:%d" % (name, PORT))
        cleanup()
        return 0
    log("FAIL", name + " денсаулық тексеруінен өтпеді")
    if previous and rollback(previous):
        log("DONE", "кері қайтарылды: " + previous)
    return 1


if __name__ == "__main__":
    os.makedirs(RELEASES, exist_ok=True)
    if "--status" in sys.argv:
        print("қазіргі нұсқа:", current_release())
        print("барлық нұсқалар:", ", ".join(releases()) or "жоқ")
    elif "--rollback" in sys.argv:
        names = releases()
        cur = current_release()
        older = names[:names.index(cur)] if cur in names else []
        if not older:
            sys.exit("кері қайтатын нұсқа жоқ")
        sys.exit(0 if rollback(older[-1]) else 1)
    else:
        sys.exit(deploy())
  1. python3 build.py → python3 deploy.py. Шығуы керек: BEGIN → UPLOAD (3 файл) → SWITCH → START (pid, порт 8081) → DONE.
  2. Тексеру: curl http://127.0.0.1:8081/health → нұсқа 1.0.0. python3 deploy.py --status → қазіргі нұсқа және барлық нұсқалар.
  3. app/VERSION → 1.1.0, python3 build.py && python3 deploy.py. Енді STOP жолы да шығады (ескі процесс тоқтатылды). Браузерде нұсқа 1.1.0.
  4. server/ қалтасын VS Code-та ашып, құрылымын сипаттаңыз: releases/ ішінде неше нұсқа? current.txt ішінде не жазылған? app.pid не үшін керек?
  5. Түсіндіріңіз: неге жаңа нұсқа ескісінің үстіне жазылмай, жеке қалтаға ашылады?

Есепке: deploy.py, екі орналастырудың шығысы, server/ құрылымы, сұрақтарға жауап.

4-тапсырма. Денсаулықты тексеру және кері қайтару (20 мин, 15 ұпай)

deploy.py ішінде health_check және rollback заглушкаларын өшіріп, орнына төмендегі кодты толық жазыңыз.

Файл: deploy.py — health_check және rollback орнына

def health_check(tries=5):
    url = "http://127.0.0.1:%d/health" % PORT
    for i in range(1, tries + 1):
        try:
            r = urllib.request.urlopen(url, timeout=2)
            log("HEALTH", "%d-әрекет: %d %s" % (i, r.status, r.read().decode()))
            return True
        except Exception as e:
            log("HEALTH", "%d-әрекет: %s" % (i, e))
            time.sleep(1)
    return False


def rollback(previous):
    log("ROLLBACK", "алдыңғы нұсқаға қайту: " + previous)
    stop_app()
    switch(previous)
    start_app(previous)
    return health_check()
  1. app/VERSION → 1.2.0, python3 build.py && python3 deploy.py → HEALTH «1-әрекет: 200 ...» → DONE.
  2. Қате нұсқа: app/VERSION → broken (бұл нұсқада /health 500 қайтарады), python3 build.py && python3 deploy.py. Шығуы керек: HEALTH 1–5-әрекет: HTTP Error 500 → FAIL → ROLLBACK → START 1.2.0 → DONE «кері қайтарылды». Шығу коды: echo $? → 1.
  3. Сайт тоқтады ма? curl http://127.0.0.1:8081/health → 1.2.0.
  4. Қолмен кері қайту: VERSION → 1.3.0, құрастырып орналастырыңыз, содан кейін python3 deploy.py --rollback → алдыңғы нұсқа.
  5. Түсіндіріңіз: неге денсаулық бірнеше рет (5 әрекет) тексеріледі? Кері қайтару неге алдыңғы нұсқа сақталғандықтан ғана мүмкін?

Есепке: өзгертілген код, сәтті және сәтсіз орналастыру шығысы, --rollback нәтижесі.

5-тапсырма. Журнал, тазалау және CI/CD құбыры (20 мин, 15 ұпай)

deploy.py ішінде log және cleanup заглушкаларын ауыстырыңыз, pipeline.py файлын жасаңыз.

Файл: deploy.py — log орнына

def log(step, message):
    line = "[%s] %-8s %s" % (time.strftime("%H:%M:%S"), step, message)
    print(line)
    os.makedirs(SERVER, exist_ok=True)
    with open(os.path.join(SERVER, "deploy.log"), "a", encoding="utf-8") as f:
        f.write(json.dumps({"time": time.strftime("%Y-%m-%d %H:%M:%S"), "step": step, "message": message},
                           ensure_ascii=False) + "\n")

Файл: deploy.py — cleanup орнына

def cleanup(keep=3):
    cur = current_release()
    others = [n for n in releases() if n != cur]
    old = others[:len(others) - (keep - 1)]        # қазіргі + соңғы (keep-1) нұсқа қалады
    for n in old:
        shutil.rmtree(os.path.join(RELEASES, n))
        log("CLEANUP", "ескі нұсқа жойылды: " + n)

Файл: pipeline.py

# pipeline.py — CI/CD құбыры: тексеру -> құрастыру -> орналастыру -> smoke-тест
import subprocess
import sys
import urllib.request

STEPS = [
    ("1. ТЕКСЕРУ", [sys.executable, "-m", "py_compile", "app/app.py"]),
    ("2. ҚҰРАСТЫРУ", [sys.executable, "build.py"]),
    ("3. ОРНАЛАСТЫРУ", [sys.executable, "deploy.py"]),
]

for title, cmd in STEPS:
    print("=" * 50)
    print(title, ":", " ".join(cmd[1:]))
    if subprocess.run(cmd).returncode != 0:
        print("ҚҰБЫР ТОҚТАДЫ:", title, "сәтсіз аяқталды")
        sys.exit(1)

print("=" * 50)
print("4. SMOKE-ТЕСТ: басты бетті ашу")
page = urllib.request.urlopen("http://127.0.0.1:8081/", timeout=3).read().decode("utf-8")
if "Алматы экономикалық колледжі" not in page:
    print("ҚҰБЫР ТОҚТАДЫ: бет дұрыс емес")
    sys.exit(1)
print("бет ашылды ·", page.split("<b>")[1].split("</b>")[0], "нұсқасы")
print("ҚҰБЫР СӘТТІ АЯҚТАЛДЫ ✔")
  1. VERSION → 2.0.0, python3 pipeline.py. Шығуы керек: 1. ТЕКСЕРУ → 2. ҚҰРАСТЫРУ → 3. ОРНАЛАСТЫРУ → 4. SMOKE-ТЕСТ «бет ашылды · 2.0.0 нұсқасы» → «ҚҰБЫР СӘТТІ АЯҚТАЛДЫ ✔».
  2. app/app.py-ге әдейі синтаксис қатесін енгізіп (мысалы, бір жақшаны өшіріп), python3 pipeline.py → «ҚҰБЫР ТОҚТАДЫ: 1. ТЕКСЕРУ». Сайт ескі нұсқамен жұмыс істеп тұр ма? Қатені түзетіңіз.
  3. Тағы 2–3 нұсқа орналастырыңыз: CLEANUP жолдары шығады, server/releases/ ішінде 3-тен көп нұсқа қалмайды.
  4. server/deploy.log файлын ашыңыз: әр жол — бір JSON жазба. Соңғы орналастырудың барлық кезеңін табыңыз.
  5. Құбырдың сызбасын салыңыз: код → тексеру → құрастыру → жеткізу → ауыстыру → health → (сәтсіз болса) rollback.

Есепке: өзгертілген код, pipeline.py, сәтті және тоқтаған құбыр шығысы, deploy.log үзіндісі, сызба.
